# Value Investing Portfolio Decisions

这是针对 Portfolio Watch assignment 的完整实现目录：一个受用户能力圈约束的长期价值投资决策 Skill，以及基于 Alva 数据运行的公开 Playbook Dashboard。

它不试图预测明天涨跌，也不要求用户每天交易。它每天刷新证据，只有估值、安全边际、投资逻辑、风险或模型仓位发生足以改变判断的变化时，才进入买入、持有、减仓或退出复核。

## 设计理念 & Skills 介绍

### 1. 我对 Alva 的核心思考

Alva 的优势不只是回答问题，而是通过 Skill 和 Agent 接入、整合公司的基础信息、市场数据、资讯和新闻，再把这些分散信息转化为可持续更新的决策依据。它可以帮助用户把复杂数据组织成指标和判断，这是非常有价值的产品方向。

但空白对话框也带来了使用门槛。大多数用户不知道应该问什么，也不知道如何把财务指标、新闻和市场信号组合起来。Alva 更适合先了解用户熟悉的行业、关注的标的、投资期限和风险承受能力，再推荐或生成对应的 Playbook，让用户先看到一个明确的决策方案，而不是被要求自己发现产品能力。

### 2. Skill 如何设计

Skill 的整体设计分为“明确需求、建立约束、形成证据、交叉验证、输出决策”五个环节。

首先借鉴 Grill Me 的思想，不直接根据用户最初的一句话开始分析，而是通过多轮问答明确用户真正希望解决的决策、能力圈、关注标的、投资期限、风险承受能力、成功标准和行动边界，并把结果整理成经过用户确认的 Goal Brief。这样可以先区分用户的目标与其提出的方法，避免在需求仍然模糊时生成看似完整但并不适用的结论。

在需求明确之后，Skill 借鉴 TradingAgents 的多 Agents 辩论形式：先为每个标的建立统一的证据包，再由商业质量、基本面、估值、行业周期和投资逻辑等角色独立分析；随后由 Bull 和 Bear 基于同一组事实进行交叉质询，保留尚未解决的分歧；最后由投资逻辑风险、组合风险和仓位角色复核，并由 Portfolio Manager 综合裁决。这个过程不是简单投票，而是要求每个结论都能对应证据、假设、冲突和风险约束，从而提升投资结论的置信度、可解释性和可追溯性。

完整流程是：多轮需求澄清 → 确认 Goal Brief → 固化能力圈、标的范围和投资政策 → 建立共享证据包 → 独立角色分析 → Bull/Bear 辩论 → 风险与仓位复核 → 形成买入、持有、减仓、退出或继续研究的决策 → 生成并持续更新 Playbook。通过这些前置约束和决策闸门，Playbook 不只是展示市场信息，而是输出更符合用户真实需求、认知范围和投资倾向的决策方案。

### 3. 对价值投资的作用

这个 Skill 不预测明天涨跌，而是每天回答三个长期问题：价值有没有改变、价格是否提供安全边际、风险是否值得继续承担。

Playbook 用四个视图展示今日决策、Bear/Base/Bull 估值区间、逻辑风险和方法流程。买入必须通过估值、投资逻辑、风险和仓位检查，并按目标仓位分批建立；持有是正式结论；卖出则区分逻辑破坏、价值实现和仓位风险。Learning Circle 只进入研究，不直接产生买入动作。

它最终想减少三种错误：在认知范围外下注，把下跌机械地当成便宜，以及投资逻辑已经改变后仍然拒绝行动。它提供的是可追溯的决策支持，不承诺收益，也不自动下单。

- `validation/`：Skill 测试提示和验证记录。

链接：[Mag 7 Value Decisions](https://alva.ai/u/1148973244/playbooks/mag7-value-investing)
四个 Tab 都读取同一批 Automation 输出：

1. **今日的决策**：估值位置、财报事件和 Bear/Base/Bull 区间图。
2. **估值区间**：当前价格与三种估值情景，以及买入、减仓、退出复核线。
3. **逻辑风险的判断**：角色证据置信度雷达、正负立场图、Bull/Bear 依据、冲突、证据缺口和逐角色证据账本。

## 数据与角色实现

当前示例观察范围是 Core Circle 的 AAPL、MSFT、GOOGL、AMZN、NVDA、META、TSLA，以及只用于研究的 Learning Circle：TSM、AVGO、AMD。价格、公司资料、市值、P/E、EPS 一致预期、财务指标、行业 ETF 回报和财报日期来自 Alva Arrays。

在设计层面，每个标的先形成同一时间批次的共享证据包，再按 Business、Fundamental、Valuation、Industry/Cycle、Thesis、Bull、Bear、Thesis Risk、Portfolio Risk 和 Position 角色进行独立分析、交叉质询和风险复核。当前线上 Playbook 使用 `INDEPENDENT_RULE_BASED_PASSES` 实现这一角色架构：角色分数来自真实 Arrays 输入上的透明规则推导，不是随机数，也不冒充已经完成的开放式 LLM 辩论。角色立场分数和证据置信度分开显示；置信度表示证据质量，不是盈利概率。

因此，README 中的“多 Agents 辩论”描述的是 Skill 的决策架构和角色协作契约；公开 Playbook 当前展示的是可审计的规则化实现。未来接入真正的独立 Agent 调用时，仍需沿用同一共享证据、引用、冲突保留和风险闸门。

估值区间使用未来四季度 EPS 中位数共识，必要时降级到下一财年或 `EPS_TTM`，再乘以业务模型的 Bear/Base/Bull 政策倍数。Core Circle 默认单标的模型上限为 10%、目标 8%、分 4 批；没有连接真实持仓、现金、成本、税务和相关性，因此页面只显示模型容量，不生成个人下单金额。

## 重要边界

- 规则角色检查不是具备独立信息搜索和开放式辩论能力的完整 LLM 多 Agent 委员会；实现边界在 Playbook 第三个 Tab 中公开展示。
- 行业角色以行业 ETF 相对回报作为周期代理，不替代同行经营数据、产业链研究或管理层访谈。
- 价格进入买入线只触发复核，不自动成交；价格下跌也不会单独构成止损理由。
- Learning Circle 只输出 `RESEARCH_ONLY`，不会生成直接买入动作。
- 这是研究和决策支持工具，不构成个性化投资建议，不保证收益或决策正确率。
